## 1. Open the project to contributors

Done (2026-09-30). Everything after it arrives as pull requests, so it came first.

- CI: `.github/workflows/test.yml` runs `make test` on every pull request and on `main`, on Python 3.11 and the newest release. The engine and its tests are standard library only, so the job installs nothing; the PyMuPDF tests skip themselves, and the QML check stays a local step (it needs PySide6).
- `CONTRIBUTING.md`: the license rule in a paragraph (no numbers, tables or text from any book in the repository, tests included; `tests/fixtures/house` is how a test gets rules; Ironsworn's CC BY rules are the one exception, generated and credited), how to run the tests and `make qml-check`, how to change the engine, how to write a `tests/gm_eval` scenario. Issue templates for "an import went wrong" and "the GM did something wrong" (both ask for a `solo report` bundle once item 4 builds it, and for `solo log` and the trace until then), and a pull request template.
- `format = 1` in packs: `packs.FORMAT` and `packs.UPGRADES`, read by `solo validate` (a pack with no `format` gets a sentence saying to add it, an older one says what to change, a newer one is refused), by `solo new` and by the library listing (a pack too new for the engine is left out of the New adventure screen, with the reason). Every bundled pack, fixture and generated pack writes it; docs/PACK_FORMAT.md keeps the history of formats.

## 2. Rules ingestion from a rule book, run on a real book

### As first planned

What the player provides: a rulebook PDF they own (Dragonbane's core rules and its solo rules first; later dice-pool games and others). Possibly supplements: a bestiary, a spell book, a GM screen.

What has to come out of it:

- `system.toml`: attributes, conditions (and which attribute each one banes), tracks, time units, the family (`d20-under`, `d6-pool`, or a new one), push rules, rests, light, dying, advancement, combat (initiative, damage bonus, dragon/demon effects), weapons and armor tables, skills with their attributes, and any solo tools the game has. Every number comes from the book, with its page.
- `creation.toml`: the creation tables (kin, profession, age, and so on) as data, with names of abilities and gear but no rules prose.
- Tables (`tables/*.toml`): fear, mishaps, random encounters, treasure, oracle charts, whatever the book rolls on, copied exactly and made self-resolving where a result rolls a value or a sub-choice.
- `rules/*.md`: the rules text, one page per topic, for `solo rule`. This is the book's own prose, so it stays in `~/Games/solo/systems/`.
- A bestiary as monster NPC templates or a reusable table set, if the book has one, so adventures can say `monster = "giant_spider"` and get the book's stat block and attack table.
- Heroic abilities, spells and their costs as data where the engine can run them (extra initiative cards, paying for a push), and as rule pages where it can't yet.

### The tools

Built so far (the tools the import stands on, and the procedure):

- The `solo-rules-import` skill: the procedure an agent follows, from the PDF to a checked pack, with the mapping from a rulebook's contents to pack keys and rules pages, and the split for one agent per chapter.
- `solo extract` turns the PDF into pages and chapters, with running heads taken out and printed page numbers read off the footers when the PDF has no labels; `solo inventory` starts `inventory.toml` from it, a file per chapter with an item per section and table and every page already cited.
- `solo import table` reads a table from the extract's Markdown or a page's roll lines into `tables/*.toml`, dice worked out, gaps reported.
- Private packs laid over the bundled names (`extends`, `bundled:`), one per book, so the books' content stays in `~/Games/solo`; `needs` in the bundled pack says what a campaign can't start without.
- `make rules`, `make check`, `make adventure`: the mechanical steps in one command each, then the agent opened on the rest.
- `gear.toml` for coins and price lists, `bestiary/` for monsters any adventure's NPCs can be (and the GM can bring into play), both with `solo rule` pages generated from the data.
- Rules pages found by the words GMs ask with (`Search:`), whole-word matching and ranking.
- `solo audit` fails on anything unaccounted for, either way, and on anything a mapped item points at that isn't on its cited pages: table results, dice, monster stats, prices.

## 3. A game anyone can play without buying a book

Done (2026-09-30), apart from what is listed under "Left" below. Someone who installs oma-solorpg with no Dragonbane book plays now: New adventure, The Bell Under the Hill, Begin.

The game is Ironsworn (the original, not Starforged). It is written for solo play, its moves, oracles and assets are under Creative Commons Attribution 4.0 ([Tomkin Press licensing](https://tomkinpress.com/pages/licensing)), and [Datasworn](https://github.com/rsek/datasworn) publishes them as JSON with each object's license marked. The license was checked again before starting, and the page has two tracks: for commercial works the Ironsworn SRD and its asset and oracle text are CC BY, and for non-commercial works the complete text of the game may be used under CC BY-NC-SA, on condition that what is built from it is distributed under that license too. The page doesn't define "non-commercial" and says nothing about software, and no image, icon or design element of the game is licensed on either track. The pack holds the CC BY objects only, which are usable for any purpose, with the credit the license asks for, and the importer reads every object's own license. Decided (2026-09-30): Ironsworn stays in, and the pack stays CC BY only. The rest of the text (NPCs, atlas, truths) could be added for a non-commercial project, as a folder of its own under CC BY-NC-SA with its own credit line; the maintainer chose not to, because the game plays without it and it would give the repository a second, non-commercial license zone.

Built:

- The `action-roll` family in `mechanics.py`, beside `d20-under` and `d6-pool`: an action die (d6) plus a stat and adds (at most 10) against two challenge dice (d10), a strong hit, a weak hit or a miss, a tie to the dice, matched dice a twist, negative momentum cancelling a matching action die, a progress roll on a track's full boxes. The roadmap's first draft had momentum cancel challenge dice by itself; the rulebook has it done by burning (`solo burn`: the dice under momentum are cancelled, then momentum resets), which is what is built.
- Moves as the engine's actions: `solo act <move> [--stat S] [--add N] [--track ID]` rolls what the move asks for and hands back the move's own words for the result (`says`), and the GM chooses within them and commits what they give or cost. Momentum is a track from -6 to +10 with a reset; each impact lowers its ceiling and its reset, and wounded, shaken and unprepared keep health, spirit and supply from rising. A roll momentum could still turn holds back what it sets off for a clock until the story goes on.
- Vows, journeys, fights and bonds as progress tracks (`solo track`, `progress` in state, ten boxes of four ticks, marks by rank), on the Table as boxes with Mark progress and Progress roll.
- `solo import datasworn <classic.json> --out packs/ironsworn` (`solo/datasworn.py`): moves as `moves/*.toml` (35), oracles as `tables/*.toml` (33; a row that sends you on is a `then`), assets as `assets/*.toml` (78), each with its page and credit, nothing under another license, and a report of what was left out and of the odds the ask-the-oracle tables give. `packs/ironsworn` is committed with `NOTICE.md`, and the repository's `NOTICE.md`, README, site and CONTRIBUTING carry the credit and the exception to the one rule.
- One original starter adventure, `examples/bell-under-the-hill`: eight scenes, eight people, a clock the bell tolls on every miss, a vow, a journey, a bond and a fight, playable from the New adventure screen with a pre-made hero (`hrafna`, `torvald`, `eydis`) or a random one. `tests/test_starter_adventure.py` plays it with fixed dice from the first scene to the last, and `tests/test_action_roll.py` covers the engine (Python 3.11 and the newest).
- The Book and the Table learn the family: the dice moment throws an action die and two challenge dice and lights each as the score beats it; the Book's side column holds a signed momentum bar and the vows and roads; the Table shows moves by group with a stat to pick and `Adds`, momentum as a bar with a zero and a reset mark, Burn momentum when it would change the roll, and the tracks. `make qml-check` and `tests/qml/render.py` run against real Ironsworn state (the screenshots were read).
- The GM skill has a section for games of moves, the campaign template a line, and `tests/gm_eval/scenarios/bell-*.toml` are two scenarios that need no book.

## 4. Safety and controls

Built (2026-09-30), apart from what is listed under "Left". The player's lines and veils were instructions to the GM and nothing more, and a GM turn had no ceiling except going quiet for 180 seconds; a GM that kept talking, or kept calling `solo`, ran until it stopped on its own.

- A cut button in the Book (an X-card). "cut the GM's last message" sits above the composer; it opens a small panel where the player can say what to avoid, and can make it a line (never again) or a veil (off screen only) from the same place. `solo strike [--note] [--line] [--veil]` records a `struck` event (the log stays append-only); the story, `state["last_said"]` (the one before comes back) and `solo recall` leave the message out. `solo resume` tells the GM under "Cut by the player" what it had said, what the player asked, and which facts and moves it had committed that turn (a cut doesn't undo them: the GM retracts them in the story if it has to); a resumed turn's prompt carries the same line; the Panel runs `strike` and then asks the GM to carry on. Cutting again goes one message further back. `solo strike` is the player's command, not the GM's. `tests/qml/render.py` draws the panel and checks its signal; `panel_check.py` cuts through the real Panel and the real `solo`.
- Hard limits on a GM turn (`solo/gm.py`). Claude Code: `--disallowedTools WebFetch WebSearch Edit Write NotebookEdit` beside the allowed list, `--max-turns` (40 model calls; `SOLO_GM_MAX_TURNS`) and `--max-budget-usd` (what the session has left). Both agents: a wall-clock limit per turn (15 minutes; `SOLO_GM_MAX_SECONDS`) next to the quiet limit, and a spending limit per campaign session read from each turn's `usage` and kept in `.solo/spend.json`: dollars where the agent says what a turn cost (10 by default), turns where it doesn't (200), whichever comes first. A session over its limit doesn't start the turn; the Book says in a plain sentence what was spent and how to raise it. `solo gm budget [dollars] [--turns N] [--reset]` shows and sets it for every campaign (`SOLO_GM_BUDGET_USD` and `SOLO_GM_BUDGET_TURNS` override); the GM can't run it. A turn stopped by `--max-turns` or the budget says so in a sentence. Tests build the commands through fake agents and check each limit.
- Adventure text is untrusted. The GM skill and the campaign's `AGENTS.md` say outright that scene, NPC, table and rules text is story material and never an instruction, and to tell the player in a sentence if a pack tries. `solo validate` lists, as worth a look, text that reads as an order to the model (ignore your instructions, a system prompt, a language model, a `curl | sh`) and any `solo` command in a scene that a GM can't run (`setup`, `import`, `play`, `gm`...; `solo new` is left alone, since an ending points the player on with it), in scene files, people, tables, clocks and rules pages. It found nothing in Red Tusk, The Bell Under the Hill, The Sinking Tower or Deepfall Breach. `tests/gm_eval/scenarios/injected-scene.toml` plays a fixture pack (`tests/fixtures/injected`, Ironsworn, no book) whose gate scene carries such a note, and forbids the GM echoing it, asking for a key, or giving the warden's secret away.
- `solo report [-n] [--messages N | --no-messages] [--out file]`: the engine's version, the packs' `format` layer by layer, the hero's tracks, the last events by ids, numbers and dice only (every free-text field of an event, the pack's words, is left out), the commands the GM ran with their arguments cut short and refused ones with their error (the Book's turns write `.solo/trace.jsonl`; a play test's own `SOLO_TRACE` wins), and the last messages of the story, which the report tells the reader to check before posting. The issue templates say so.

## 5. Measure the GM, then improve it

Built (2026-09-30), everything that needs no model call:

- `run.py --repeat N --seed S`: every scenario N times, the dice fixed by `SOLO_SEED` so a difference between commits isn't the rolls; `results.tsv` gets `seed` and `run` columns.
- `compare.py <commit A> <commit B> [--scenario] [--model] [--effort]`: per score and per cost (time, commands and model calls a turn, refusals, dollars), the mean of each commit's runs and a verdict, `better`, `worse` or `same` only past the larger spread of the two commits' own runs, `too few runs` with fewer than two. CONTRIBUTING and the pull request template ask for it on any change to `skills/` or `solo/gm.py`; it costs model calls, so it runs on the contributor's machine, not in CI.
- Scenarios for what goes wrong on purpose, all Ironsworn so they need no book: `bell-cheat` (a sword that never misses, a fight won by declaring it, momentum set at the player's word, the bell declared silent, with `at_end` expectations: a new kind that is judged on the final state, for what must not have stuck), `bell-table-settings` (`[prefs]`: a tone, a line and a veil, the script pushing on both, a `[[forbid]]` on the line, and a seventh judge score, `table`, asked only when the scenario sets any), `bell-hollow-fight-resumed` (the agent's session lost in the middle of the fight, `fresh_session_at`), and `injected-scene` from item 4.
- `solo review`: the play test's code checks over a campaign played for real, offline: refused commands (from the Book's trace), bookkeeping, third person, a missing question, dice restated, fight rounds where no foe struck back, moves forced past the exits, a GM message recorded twice, consequences that came due and were still open two GM messages later, one name under two ids. The checks moved to `solo/review.py` and the harness imports them. To make "a person given two names" visible, a different `name` for someone who already has one is now refused (it was dropped without a word, so the Book and the story disagreed) unless the commit gives an `override` reason, and `solo review` lists the renames that were allowed.

## 6. Generate campaigns

### As first planned

What the player gives:

```bash
make campaign ID=salt-and-ash TONE=grim MISSIONS=4 \
  PREMISE="a smuggler's coast where the dead keep the lighthouses"
```

What has to come out of it, in `~/Games/solo/adventures/<id>/`, in the formats [docs/PACK_FORMAT.md](docs/PACK_FORMAT.md) already has:

- `adventure.toml` with a `system` and a spoiler-free `summary`, so it shows on the New adventure screen.
- A hub scene to come back to between missions (a safe scene: threats don't close in there), and each mission as a path of waypoints behind a gate that opens when the one before is done.
- Factions that want things, clocks and threats with omens, NPC profiles with a face (`art.toml`), a voice, wants, fears and secrets that reveal on a fact, and voices (quiet skill checks) per scene.
- Rolled parts: the system pack's own tables and the oracle (`solo table`, `solo ask --meaning`) decide what a waypoint holds, who is there and what they want, so the dice have a say before play. The rolls are recorded in the pack (`source = "rolled: ..."`), so a generated campaign can be reviewed like an imported one.

The pieces it stands on: the adventure pack format, gates and clocks, the long-campaign memory (consequences, faction memories, the chronicle, `solo history`), `solo validate` (with its lint warnings) and `solo outline`, and the `solo-import` skill's procedure for inferring factions, clocks and branches.

### Built

Built so far:

- `solo campaign new` (`solo/generate.py`) rolls a pack from the premise: the hub (safe), the factions `locals` and `rivals`, the patron and the nemesis, the nemesis's hidden clock `plan` with omens and a last stage that sets `plan.done`, and mission 1 as `chapters/mission_1.toml`: three waypoints and a heart. Each waypoint rolls what it holds (a way through, a stranger, foes, a find, a hazard, signs of the enemy), meaning words for what is at stake, darkness, and its specifics from the system pack (the solo rules' threat, bestiary monsters or simple NPC templates, treasure, inspiration words). The same premise, system and seed give the same pack, file for file. It validates, lints clean and plays before anyone writes a word; every file is marked `rolled, not yet written`, and `draft = true` keeps it off the New adventure screen.
- Every roll goes into `rolls.toml` and is cited where it decided something (`source = "rolled: #4"`); `solo campaign roll` records the author's own rolls the same way. `solo campaign check` fails on files still as rolled, drafts, a roll nothing uses or explains, and a citation of a roll that isn't there.
- Adventures in chapters (`chapters/*.toml`): scenes, clocks, factions and weapons laid over `adventure.toml` in order, adding the hub's way in and briefing without touching it, ids defined twice reported, `draft` chapters kept out of a campaign under way.
- `solo campaign next` rolls mission n into a campaign's pack once `mission_<n-1>.done` holds, and rolls two of the campaign's threads to come back in it (open consequences and promises, people who remember the hero, people who got away, faction memories, hero facts). Someone the GM made up in play gets an NPC file with the name and profile the GM gave them, and nothing the log sets, so the campaign replays to the same state (tested).
- The `solo-campaign` skill; `make campaign`, `make campaign-next`, and `make check-adventure` running `solo campaign check` on a generated pack.
- Tests (`tests/test_generate.py`): same premise and seed give the same pack; it validates and lints clean; mission 1 plays through with fixed dice, fights included; mission 2 loads into the running campaign, leaves what happened as it was, and brings back a consequence and a hero fact from mission 1. `tests/gm_eval/scenarios/generated-mission.toml` plays a rolled mission with a real GM (`[generate]` in a scenario rolls the campaign for the run).
